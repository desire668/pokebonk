# 2026-10-19

## PokéBonk iOS 壳（仓库 desire668/pokebonk）

把 https://pokebonk.app/zh-cn/ 这个在线 3D 宝可梦幸存者游戏包成 iOS App，产出未签名 IPA，用户自签。

- 技术选型：XcodeGen(`project.yml`) 生成工程 + 纯 UIKit + WKWebView，GitHub Actions(macos-15) 里
  `xcodebuild archive` 全程 `CODE_SIGNING_ALLOWED=NO`，再 zip 成 Payload/xxx.ipa。
  选 XcodeGen 而不是手写 pbxproj：本机是 Windows，无法生成/校验 xcodeproj。
- 控制方案：左半屏下方浮动摇杆 → WASD；右半屏拖动 → 视角；右下四键 R/E/Space/Shift。
  输入靠 `InputBridge.js`（atDocumentStart 注入）下发。

### 游戏输入机制（逆向主 bundle 得到，很关键）
- 键盘：`keydown/keyup` 读 `e.code`（KeyW/A/S/D、Space、ShiftLeft、KeyR、KeyE…），
  监听在 window/document 层；`e.target` 是 INPUT/TEXTAREA/SELECT 会被跳过 → 从 canvas 派发最稳（会冒泡到 window）。
- 视角：`mousemove` 读 `e.movementX/movementY`。
  · `locked` 为真（pointer lock）时无条件累加；
  · 否则需 `dragLook && (buttons&1 或 requestPointerLock 不是函数) && e.target === 锁定元素`。
- `requestLock()` 只在游戏内部 `Pi`(wantLock) 为真时才锁；强行伪造 pointerLockElement 会被
  `pointerlockchange` 里的 `!Pi` 分支立刻 `exitPointerLock` 撤销。
  → 因此 InputBridge 做了 requestPointerLock 垫片 + 退避重试（用户开始拖视角时 forceLock，另每 4s 试一次）。
- iOS 无真 pointer lock；应用里另留「触屏拖拽」方案（合成 pointerType=touch 的 PointerEvent）作为兜底，可在设置里切换。
- 游戏用 `(hover:hover)` 判定桌面/触屏（`di`），UA 改不了这一点，故仍以桌面 UA 运行。
